# AskToto — Enterprise Refinement Backlog

Distilled from 29 expert findings (Apple CMO · Principal Designer · Senior Engineer) into 27 deduplicated, prioritized items.
Order: **P0** broken/unsafe first, then **P1** high-value UX/design/perf wins, then **P2** polish. Each item is checkbox-tracked — work top-down.

## P0

- [x] **1. Auto-start records both call sides on a 6s notice — consent/GDPR breach** — area: `src/renderer/src/components/MeetingDetectedToast.tsx` (40, 55-59), `src/renderer/src/components/Settings.tsx` (2405-2427) · effort: M · fix: Make auto-start opt-**IN** — the detection toast's primary action becomes "Start listening" and captures nothing until clicked; keep the persistent `RecordingConsentReminder` banner up for the whole session instead of relying on the 6s toast; default `autoStartOnMeeting` off for enterprise builds (or gate behind an explicit "I'll always inform participants" confirm). · _accept:_ With auto-start on, detecting a Teams/Zoom call shows a "Start listening" prompt and records nothing until clicked, and once listening a consent banner stays visible the entire session.
- [x] **2. CLI negative-cache blocks in-app install→connect until app restart** — area: `src/main/cli.ts` (54-65 `resolveBin`, 486-568 `installCli`) · effort: S · fix: Cache only non-null resolutions (skip `binCache.set` when `resolved===null`), or invalidate via `binCache.delete(cfg.bin)` at the end of a successful `installCli`/`setupCli`/`loginCli`. · _accept:_ Install a CLI in-app then Test/Connect in the same session (no restart) reports connected.
- [x] **3. Rapid stop()→start() race tears down the freshly-started Listen session** — area: `src/renderer/src/lib/listen.ts` (311-383 `start`, 526-583 `stop`/`finishTeardown`) · effort: M · fix: Add a monotonic session epoch captured in `start()`; `waitForDrain`/`finishTeardown` bail early if the epoch changed; clear any pending drain timer and reset `stoppingRef.current=false` at the top of `start()`. · _accept:_ Double-tap stop then start (or auto-start right after `endReview`) keeps audio live and the UI "listening", and the next real Stop still works.
- [x] **4. Silent forever-spinner when failover exhausts on an "ineligible" provider** — area: `src/main/index.ts` (939-943, `attempt` → ineligible branch) · effort: S · fix: Mirror the allowed-branch — `else if (!failover(attempted.concat(provider))) win?.webContents.send(IPC.streamError, { id: req.id, message: ineligible })`. · _accept:_ When the last failover candidate is ineligible (e.g. Dust without `dustWorkspaceId`), the renderer receives a terminal error and stops spinning.
- [x] **5. Vision screenshot cache keyed on time only → answers about the wrong monitor** — area: `src/main/index.ts` (356-403 `getScreenshot`/`shotCache`), `src/renderer/src/components/Bar.tsx` (166) · effort: S · fix: Include display id in the cache (`{ ...shot, dispId, ts }`); treat as a miss when `disp.id !== shotCache.dispId`; compute `disp` once and thread it through `captureScreenshot`. · _accept:_ Focusing the input on monitor A then asking a vision question with the cursor on monitor B returns an image of B, not A.
