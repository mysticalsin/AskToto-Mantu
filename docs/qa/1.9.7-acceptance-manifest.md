## Scope and decision

This manifest covers the approved **unsigned, manual-install 1.9.7 owner-channel prerelease**. Its acceptance target is the exact Windows and macOS installers and their downloaded bytes. A successful source build, a green CI workflow, or a synthetic self-test is not packaged installation evidence.

The public [Metis-Releases feed](https://github.com/mysticalsin/Metis-Releases/releases) currently lists unsigned/ad-hoc 1.9.6 as its newest release; no 1.9.7 release is listed. No 1.9.7 installer SHA, candidate provenance, or published asset set is recorded here. **This manifest does not claim release readiness or publication.**

Unsigned owner-channel prerelease publication is the intended milestone. It must stay a prerelease and manual-install channel. The candidate promotion workflow publishes prereleases without `latest*.yml` updater manifests; that is expected for this scope. Signed stable distribution, notarization, Authenticode, and trusted automatic-update E2E are deferred and are not blockers for this milestone. Manual upgrade, data preservation, and recovery remain in scope.

The broader 2.1 roadmap and its 20-scenario mandate are separate. Nothing in this document marks 2.1 acceptance complete or imports its requirements as a 1.9.7 gate.

## How to read this manifest

- **PASS** — the named criterion passed on the linked evidence revision. The row states what that evidence does and does not prove.
- **FAIL** — linked evidence records a failed required check, or the observed source behavior fails the criterion.
- **SKIPPED** — the named workflow explicitly skipped the check; skipped is not a pass.
- **NEVER RUN** — no exact candidate or report was found for the criterion at this snapshot.
- **BLOCKED EXTERNAL** — evidence requires a live service, owner-controlled account, or device readback that is not present here.

Evidence labels distinguish claims: **OBSERVED** is source/configuration or public-release inspection; **PROVIDED** is a linked hosted report or PR record; **DERIVED** is a conclusion from those facts; **UNKNOWN** is unverified. PR checks are not deployment evidence. The repo rule D-28 keeps repository tests, scripts, apps, builds, and formatters in GitHub Actions; this document change did not run them locally.

## Release decision at this snapshot

**HOLD publication.** The current 1.9.7 source is identified and several security-policy changes are merged, but there is no exact main-based candidate provenance or accepted EXE/DMG evidence. The linked synthetic candidate run contains nested ST-1 and History failures. Existing-profile upgrade/recovery, deployed Operator/Cloudflare configuration, device migration readback, manual rollback, and exact-byte publication checks remain absent or blocked externally.

The accepted unsigned prerelease channel does **not** require signed auto-update manifests. Its absence is not a blocker. It also does not waive manual upgrade/rollback and data-preservation evidence, nor the need to publish only the exact tested bytes.

## Separate 2.1 roadmap

The Astra 2.1 release plan and its broader 20-scenario acceptance mandate are outside this 1.9.7 decision. In particular, this manifest makes no claim about 2.1 multilingual transcription, long-session soak, offline-model acceptance, signed stable distribution, or 2.1 package readiness. Those criteria must be tracked and evidenced in the 2.1 program artifacts, not inferred from this 1.9.7 record.
